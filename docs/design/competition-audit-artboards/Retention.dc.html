Retention policy configuration

A retention policy is an object with a lifecycle, not a number typed into a document type. It outlives the documents it governs and usually outlives whoever configured it.

1
Draft, active, retired
Draft governs nothing. Active governs documents. Retired stops new assignments while continuing to govern what it already holds — retirement must never release documents already counting.
RET-5RET-7
2
Period is a value and a unit
Seven and years, as separate inputs. A duration parsed from free text is a duration that will eventually be entered wrong.

3
The period counts from a named start event
Creation, status change, dossier closure, or a date field on the document. This is the mechanism that makes “seven years from closure” expressible without a script.

4
Policies attach to document types, one policy to many
Changing which policy a type uses reports how many existing documents it affects before it is applied.

5
The user is told, in place, that retention is in effect
With the expiry date and the policy that decided it. Users delete what they should keep when this is hidden.

This is where we part company with the market. A compliance-focused DMS deletes automatically once the period lapses. RET-12 refuses: expiry moves the document into a disposition review queue and nothing is destroyed without an explicit, audited human decision.
